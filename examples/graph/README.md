# Kinship-graph cartridge experiments

Do trainable KV-cache **cartridges** capture the relational structure of a family
tree? We train cartridges on a 45-person / 6-generation tree over a frozen
Qwen3-1.7B and probe them with controlled name-swap variants.

- **How cartridges are compared** → [`METHODOLOGY.md`](METHODOLOGY.md)
- **Where every output/checkpoint lands** → [`OUTPUTS.md`](OUTPUTS.md)
- **Findings** → [`REPORT.md`](REPORT.md) — ⚠️ all prior results are **stale** (computed
  on a dataset with a fixed MC-option bug); experiments are being recomputed.

## Dataset (current)

Multiple-choice kinship QA over the 45-person tree. **Size: 1333 QA per variant**
(1067 train / 266 test, 20% stratified hold-out), identical structure across the
4 variants. Generated by `data_gen/qagen.py` (base) and `generate_variants.py`.

**9 classes** (share = after rebalance, per variant):

| Cat | Tests | opts | share |
|----|-------|:---:|:---:|
| 1  | direct 1-hop single — father/mother/husband/wife | 5 | 9% |
| 1m | 1-hop multi — sons/daughters | 5 | 6% |
| 1w | whose-style (inverse 1-hop) — "Whose son is X?" | 5 | 15% |
| 2  | grandparent — grandfather/grandmother | 5 | 6% |
| 2m | multi — siblings/uncle/aunt/grand·son/·daughter/cousin | 5 | 21% |
| 3  | counting — children/sons/daughters/siblings/grandchildren | 5 | 15% |
| 4  | verification — "Is A B's rel?" | 3 (Yes/No/Unknown) | 18% |
| 5  | existence — "Does X have any rel?" | 3 (Yes/No/Unknown) | 7% |
| 6  | disambiguation — "Name one of X's rel" | 5 | 3% |

**Rebalanced** to a target mixture (`MIX_DEFAULT`, default on; `--no-rebalance`
keeps the raw 9625 where verification alone is 84%): reasoning classes ≈ natural
proportions, verification+existence capped to **25%** combined. Each record carries
a `hops` hop-class (1=adjacent · 2=grand/uncle/aunt · 3=cousin/distant; overall
≈ 62% / 31% / 7%) for per-hop eval. Correct-answer letters are **uniform** (5-opt:
20% A–E; 3-opt: 33% A–C). Split is **stratified by category**, random **by question**
by default (`--split-mode person` holds out whole people for a structural-
generalization test). `"None."`/`"Unknown"` are always distractors. Loss = masked
answer-letter only.

## Experiments

| # | Question | Driver |
|---|----------|--------|
| 1 | What does the *init* cache encode? (no training) | `compare.py --source init` |
| 2 | 4 cartridges, shared Alex init, different data | `train.py MODE=variants` → `compare.py --source trained` |
| 3 | ICL baseline: structured corpus vs prose (per-hop vs cartridge) | `eval.py --mode icl-cot` |
| 4 | Training stability across seeds (noise floor) | `train.py MODE=stability` → `compare.py --run-prefix` |
| — | How do K/V vectors rotate during training? | `dynamics.py` (reads `cache-step*.pt`) |

## Setup

Source the env script once per shell — it activates `.venv` and exports the
`CARTRIDGES_*` vars + `TORCHDYNAMO_DISABLE=1` (honouring anything you already
exported):

```bash
source examples/graph/scripts/env.sh
```

Sets `CARTRIDGES_DIR`, `CARTRIDGES_OUTPUT_DIR` (=`./outputs`, required by
`cartridges/__init__`), `CARTRIDGES_OUTPUT_DIR_GRAPH` (=`./outputs_graph`, graph
results root), `CARTRIDGES_WANDB_PROJECT/ENTITY`. Override by exporting before
sourcing.

**GPU.** Every model/training/eval command runs on **one** card — prefix it with
`CUDA_VISIBLE_DEVICES=<n>` (pick a free card; different runs can use different
cards). The data-gen and trained-KV compare/dynamics steps are CPU-only.

## Running experiments

All modules run as `python -m examples.graph.<pkg>.<module>` from the repo root.
🖥️ = needs a GPU (prefix `CUDA_VISIBLE_DEVICES=<n>`); 💻 = CPU-only.

### 0. Data 💻 — tree + rebalanced QA + 4 variants + narratives
```bash
python -m examples.graph.data_gen.generate_tree --n-people 45 --max-depth 6 \
    --min-kids 1 --max-kids 2 --founders 1 --spouse-prob 0.95
python -m examples.graph.data_gen.qagen                  # base QA (add --split-mode person for structural split)
python -m examples.graph.data_gen.generate_variants --new-names Alex,Ben,Carl,Dan
python -m examples.graph.data_gen.generate_narrative
for v in alex ben carl dan; do
  python -m examples.graph.data_gen.generate_narrative --tree examples/graph/data/variants/$v/family_tree.json
done
```

### Exp 1 🖥️ — init-KV compare across variants (no training)
`comparison/compare.py` builds an untrained cache per variant and compares them.
```bash
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.comparison.compare --source init \
    --names alex,ben,carl,dan --spectra --out-dir outputs_graph/exp1_init_kv
```

### Exp 2a 🖥️ — train cartridges (shared Alex init)
`training/train.py`, selected by `MODE`. Defaults: 100 optimizer steps,
checkpoint every 20. Env knobs: `MAX_STEPS`, `SAVE_EVERY`, `EPOCHS`, `LR`.
```bash
# one variant (recommended, 1 GPU each):
CUDA_VISIBLE_DEVICES=0 MODE=variants VARIANT_ONLY=alex python -m examples.graph.training.train
CUDA_VISIBLE_DEVICES=1 MODE=variants VARIANT_ONLY=ben  python -m examples.graph.training.train
# all four in one process:
CUDA_VISIBLE_DEVICES=0 MODE=variants python -m examples.graph.training.train
# longer/full run instead of the 100-step default:
CUDA_VISIBLE_DEVICES=0 MAX_STEPS=-1 EPOCHS=10 SAVE_EVERY=200 MODE=variants VARIANT_ONLY=alex \
    python -m examples.graph.training.train
```

### Exp 2b 💻 — trained-KV compare (where train-data diffs land)
```bash
python -m examples.graph.comparison.compare --source trained \
    --ckpt-root outputs_graph/exp2_train --names alex,ben,carl,dan \
    --init-corpus examples/graph/data/variants/alex/family_tree_corpus.txt \
    --localize-names Alex,Ben,Carl,Dan --spectra \
    --out-dir outputs_graph/exp2_train/compare
```

### Exp 2c — training dynamics (K/V rotation across `cache-step*.pt`)
`comparison/dynamics.py`. CPU-only unless `--init-corpus` is given (then 🖥️, it
builds the true step-0 init via the model).
```bash
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.comparison.dynamics \
    --run-dir outputs_graph/exp2_train/alex \
    --init-corpus examples/graph/data/variants/alex/family_tree_corpus.txt --spectra \
    --out-dir outputs_graph/exp2_train/alex/dynamics
```

### Exp 2d 🖥️ — cartridge accuracy (CoT) + per-hop analysis
`evaluation/eval.py` then `evaluation/analyze.py`. The checkpoint is nested under
a timestamp/uuid, so resolve it with `find`.
```bash
CKPT=$(find outputs_graph/exp2_train/alex -name cache_last.pt | head -1)
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.evaluation.eval --mode cartridge-cot \
    --checkpoint "$CKPT" --variant-dir examples/graph/data/variants/alex \
    --output outputs_graph/exp2_train/alex/eval/results.json
python -m examples.graph.evaluation.analyze outputs_graph/exp2_train/alex/eval/results.json
```

### Exp 2e 🖥️ — cross-variant eval (structure vs surface)
Run the alex cartridge on the ben test set:
```bash
CKPT=$(find outputs_graph/exp2_train/alex -name cache_last.pt | head -1)
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.evaluation.eval --mode cartridge-cot \
    --checkpoint "$CKPT" --variant-dir examples/graph/data/variants/ben \
    --output outputs_graph/exp2_train/alex/eval_on_ben/results.json
```

### Exp 2f 🖥️ — Paper-2 ablation (swap learned K or V from a donor cartridge)
```bash
BASE=$(find outputs_graph/exp2_train/alex -name cache_last.pt | head -1)
DONOR=$(find outputs_graph/exp2_train/ben -name cache_last.pt | head -1)
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.evaluation.eval --mode cartridge-cot \
    --checkpoint "$BASE" --ablate-keys-from "$DONOR" \
    --variant-dir examples/graph/data/variants/alex \
    --output outputs_graph/exp2_train/alex/eval_ablate_keys/results.json
# (use --ablate-values-from to swap V instead)
```

### Exp 3 🖥️ — ICL baseline (corpus + narrative) + cartridge-vs-ICL per hop
```bash
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.evaluation.eval --mode icl-cot --n-shot 0 \
    --corpus-path examples/graph/data/variants/alex/family_tree_corpus.txt \
    --variant-dir examples/graph/data/variants/alex \
    --output outputs_graph/exp3_icl/alex/corpus/results.json
CUDA_VISIBLE_DEVICES=0 python -m examples.graph.evaluation.eval --mode icl-cot --n-shot 0 \
    --corpus-path examples/graph/data/variants/alex/family_tree_narrative.txt \
    --variant-dir examples/graph/data/variants/alex \
    --output outputs_graph/exp3_icl/alex/narrative/results.json
# cartridge vs ICL → accuracy-by-hop & by-category tables:
python -m examples.graph.evaluation.analyze --no-detail \
    outputs_graph/exp2_train/alex/eval/results.json \
    outputs_graph/exp3_icl/alex/corpus/results.json
```

### Exp 4 🖥️ — training stability / noise floor
Seed-variation runs + compare. Edit the GPU list inside the script.
```bash
bash examples/graph/scripts/run_exp4_stability.sh
```

### One-shot pipeline
`run_all.sh` chains data → exp1 → exp2 (train+compare) → dynamics → exp3 → eval.
Skip stages with `SKIP_<stage>=1`. It launches training on the current
`CUDA_VISIBLE_DEVICES`, so set it (and `NPROC` for multi-GPU) first.
```bash
CUDA_VISIBLE_DEVICES=0 bash examples/graph/scripts/run_all.sh
```
